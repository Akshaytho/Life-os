# Life OS — Journey Hierarchy V2

## Correction

Journey V1 contains the right detailed information for an active capability, but that level of detail should not define the top-level Journey destination.

The permanent Journey destination must remain useful after days, months, and years of life history.

## Product responsibility

Journey answers:

> What am I deliberately becoming, what is active now, and what meaningful evidence shows movement?

Journey does **not** attempt to represent everything that happened in life.

Other destinations retain their own responsibilities:

- Today: immediate reality and deliberate focus
- Calendar: time, commitments, appointments, people, rest, travel, work, health
- Memory: history, facts, reflections, decisions, patterns, meaningful experiences
- Reviews: time compression across day, week, month, and later year
- You: direction, constitution, identity-level decisions

Journey receives only evidence that is relevant to an explicitly chosen capability path.

## Hierarchy

```text
/journey
  Becoming overview

/journey/travel-creator
  Travel Creator route overview (later)

/journey/travel-creator/sound-design
  Detailed active capability instrument
```

The detailed Journey V1 interface is therefore retained as the Sound Design capability view rather than discarded.

## Top-level Journey overview

The overview must answer within one phone viewport:

1. What journey is active?
2. What capability is active now?
3. What is the current technique/edge?
4. What evidence has moved recently?
5. What is the next deliberate experiment?
6. Where does this fit in the longer arc?

It should not show the full technique library, every practice entry, every reel, every learning, or every external analysis.

## Three temporal lenses

### NOW

- active journey
- active capability
- current technique
- current evidence edge
- one next experiment

### RECENT

- small evidence summary
- latest meaningful movement
- most recent retained learning or applied artifact
- no streak counters

### ARC

- capability phases across months/years
- one dominant active phase
- future phases visible but quiet
- completed phases become historical evidence
- no percent-to-finish

## Selectivity rule

A life event enters Journey only when it materially contributes evidence to an explicit capability journey.

Examples:

- friend birthday -> Calendar; possibly Memory
- doctor appointment -> Calendar / health context
- difficult week -> Reviews / Memory / drift context
- Sound practice -> Calendar + Journey evidence
- reel applying environmental sound -> Journey evidence
- random camera-career idea -> Brain Dump / Not Now unless later promoted by decision

Journey should therefore become more meaningful as life gets busier, not noisier.

## Promotion rule

Not every interest becomes a Journey.

Creating or activating a Journey requires an explicit user decision. Future labels are orientation, not commitments.

This protects current direction from temporary inspiration and compulsive switching.

## Long-period behavior

Journey should summarize instead of forcing the user through hundreds of raw records.

Raw chronology remains available inside capability detail views and historical drill-downs.

Monthly/yearly interpretation primarily belongs to Reviews and Memory; Journey receives the capability-specific slice of that derived understanding.

## Design rule

The top-level Journey overview should feel calmer and more durable than the capability detail screen.

- fewer surfaces
- stronger hierarchy
- more whitespace
- current capability instrument remains visually dominant
- recent evidence is compressed
- arc is spatial, not a dashboard card grid
- detailed craft screens may remain cinematic and data-dense

## Prototype boundary

All Journey data remains sample state until canonical persistence and event writing are implemented.

Navigation between Journey overview and Sound Design detail is real because it is read-only.
